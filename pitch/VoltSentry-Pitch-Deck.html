The problem

Public EV charging runs on weakly-authed WebSockets.

  • Chargers speak OCPP 1.6-J — JSON frames over a persistent WebSocket to a central management system (CSMS).
  • Stations are physically exposed roadside hardware on connections that are often barely authenticated.
  • They are soft cyber-physical edge nodes sitting on critical energy infrastructure.

Why it isn't already solved

Cloud CSMS platforms audit after the fact — batch analysis minutes or hours after ingestion, long after an attack has landed.

Hardware retrofits are economically dead — you cannot ship a firewall chip to millions of deployed stations.

02VOLTSENTRY
Threat model

Five attack vectors on the charging control plane.

Meter spoofing

Under-report delivered energy so a session bills near zero while real power flows. Billing fraud at fleet scale.

Grid oscillation

Synchronised rapid start/stop of high-power chargers across a cluster to swing local load and trip a distribution transformer.

Session shadowing

A parallel WebSocket handshake reusing a live chargePointId to displace or seize a legitimate charger's session.

Subtle data drift

Slow compounding falsification that stays inside every hard threshold — invisible to any rule engine.

Card cloning

A copied RFID card charging two cars at once, often at two different sites — invisible to any single site.

03VOLTSENTRY
The approach

Pure software at the transport layer.

  • A transparent reverse proxy between the charger and the CSMS. Clean traffic is relayed 8000 → 9000 untouched, both directions.
  • Sub-millisecond design budget. No hardware change. Drop-in in front of an existing CSMS — the backend never knows it's there.
  • Every frame is parsed, the session state machine is enforced, and a dual-tier detection engine scores it before it is forwarded.
  • On a Tier-1 block: drop the frame, send ChangeAvailability to the charger, close the socket 4001.

Station identity

Taken from the URL path — ws://…/ocpp/CP-04 — parsed at handshake, before any frame arrives. The proxy opens the matching upstream socket per station and keeps a pending call map so a CALLRESULT can be correlated to the CALL that produced it.

Real units

Every figure is in its real unit, read off the wire.

11 kV feeder──▶ 1250 kVA transformer
11 kV / 433 V──▶ 415 V three-phase bus
= 240 V line-to-neutral──▶ 8 × 120 kW DC chargers
~700 V · ~170 A to the car
  • A house takes one phase, ~230 V. A fast charger needs all three: 415 V between lines, 240 V from each line to neutral.
  • Transformers are rated in kVA, not volts: kVA = kW ÷ power factor. Eight bays draw 1022 kVA, so the site needs 1250 kVA. (Our hackathon build assumed 500 kVA, which eight chargers would overload 2×.)
  • The proxy reads units off the wire: a charger sending 120000 W is 120 kW, not 120,000.

06VOLTSENTRY
Multi-site network

One VoltSentry node per site, joined into a network.

Vellore site
VS-VELLORE · 8 bays ──signed──▶ federation hub
threat-intel relay ◀──signed── Chennai site
VS-CHENNAI · 6 bays
  • Each node protects its own chargers. If the hub or the WAN goes down, detection and quarantine carry on locally.
  • Every message is HMAC-SHA256 signed with that node's own key, with replay protection; TLS optional. Forged, impersonated and replayed nodes are refused.
  • A quarantine at one site becomes a blocklist entry every site enforces within a second.

What no single site can see

One RFID card can only charge one car at a time. Sites share live sessions as salted hashes (never the card number), so a Vellore card used in Chennai while still charging in Vellore is blocked: R8_TAG_CLONE there, R9_THREAT_INTEL back home.

08VOLTSENTRY
Detection engine

Tier-2 catches the one attack a rule cannot.

  • Subtle drift stays inside every hard threshold by construction — so it is not a point outlier and a threshold engine stays silent.
  • The fix is an engineered feature the proxy computes from the wire alone: energy_residual = reported register − ∫ reported power dt.
  • Honest sessions hold this near zero. Any divergence between reported instantaneous power and the accumulating energy register makes it climb monotonically.
  • Scored two ways: an Isolation Forest on the 5-dim session vector, and an offline CUSUM change-detector on the residual for corroboration and explainability.

The 5-dim vector

[ power_kw,
  soc,
  dp_dt,
  duration_sec,
  energy_residual_kwh ]

IsolationForest(n_estimators=100, contamination=0.02, random_state=42), score normalisation pinned at fit time. Alert on score > 0.65. Samples 1–2 of a session are not scored.

10VOLTSENTRY
Credibility

What is real, and what is simulated.

Real

  • OCPP 1.6-J wire format, array framing, CALL/CALLRESULT correlation
  • Per-station session FSM and transaction registry
  • All detection logic — Tier-1 rules R1–R9, Tier-2 Isolation Forest + CUSUM maths
  • Electrical units read off the wire (W/kW, Wh/kWh, V, A, Hz) and the site model in kVA
  • Multi-site federation: signed node links, shared indicators, cross-site card-clone detection
  • Active quarantine: ChangeAvailability downstream, socket close 4001, un-quarantine on reconnect
  • Forensic JSON logging and the live NOC dashboard

Simulated / in progress

  • Charger fleet physics — a CC-CV battery model, not real hardware
  • The CSMS backend — an ~80-line mock, swappable for SteVe or CitrineOS
  • The attacks — synthesised; there is no public labelled OCPP-attack corpus
  • Tier-2 baseline is fit on a recorded feed fixture, not yet an external dataset
  • End-to-end added-latency instrumentation

12VOLTSENTRY
Beyond the hackathon

A real path to production.

Protocol

OCPP 2.0.1 device model, the three security profiles (Basic / TLS / mutual-TLS), ISO 15118 Plug & Charge, smart-charging profiles.

Deployment

Built: one node per site, federated through a signed hub, TLS optional. Next: horizontal scale via cpid-consistent-hash routing, and testing inline against a real open-source CSMS (SteVe / CitrineOS).

Detection

Threat intelligence already federates across sites. Next: Tier-2 retrained on real fleet CDRs, and federated learning so models improve without sharing raw session data.

Capacity math from the measured Tier-1 cost: one instance sustains thousands of frames/sec; a 10k-charger CPO at 0.1 Hz MeterValues ≈ 1k fps — a handful of instances.
